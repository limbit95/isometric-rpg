# ADR-0001: Godot 4.7.2 isolated 2D foundation

- Status: Accepted for STEP 0
- Date: 2026-10-29

## Decision

Use a standalone Godot 4.7.2 Standard (GDScript) project for a **2D isometric action RPG**. No Unreal migration or modification. The camera is 2D; tile visuals use 64×32 diamonds. Control: WASD/arrow keys to start.

### Modules

- `game`: scene composition, input registration, flow control. No combat logic.
- `world`: TileMapLayer and walkable-floor query. No quest state.
- `player`: CharacterBody2D movement. No inventory.
- Future `combat`, `enemies`, `progression`, `inventory`, `quests` each own their components and data contracts.

### Why

A 2D-only engine and fixed editor version reduce integration decisions. Data-first assets enable AI task boundaries. Each change must have a testable acceptance gate.

### Boundaries and risks

- The initial floor TileSet is generated at runtime; it is a test fixture, not a production tileset workflow.
- Sprite movement is in screen-space axes; isometric walk animation directions and art sorting can be revised in STEP 1.
- Edge checking is tile membership, not obstacle collision/physics.
- No automated claim about gameplay feel: human verification required.
- PR CI checks parsing, runtime smoke, and structure. It does not visually validate the game.

## Next decision (STEP 1)

Implement one dummy enemy and one basic attack, separating hit boxes, hurt boxes, health, and death events. Do not add GAS, server, or deep ECS abstractions.
